# 同伴立场、互助时点与停运痕迹

本轮以23b99bee为基线。交接设计 §11要求同伴的专长、立场与独立承诺能够改变选项，必要时拒绝某种做法；但没有锁定“林澈拒绝亲自强制迁任”这一具体规则。**以下角色边界与表达是新增原型假设，不是已确认的原规格，也不是真人平衡认证。**

## 林澈是有立场的人，不是第二份相同按钮

新局增加`aftermathRulesVersion: aftermath-v1`。第20年河港现场，林澈不亲自执行强制迁任苏岚的方案；主角仍可以执行，并承担原有的维护与信任后果。她不会替主角自动否决，也不会退出队伍、获得免费行动或凭拒绝增加好感与结局分。

理由来自实际成功招募事件，而不是单个`successor`旗标：

- 安排继任入局：她记得苏岚同意接班的承诺，不以调令替本人签字。
- 暂缺继任入局：她承认自己曾留下岗位缺口，拒绝把别人的旧履历当成调令。
- 缺少可核实来源的记录只说明证据不足，不补写已经发生的承诺。

现场可追溯到真实兑现记录。查看立场不扣费、不消耗调查、不占名额；林澈仍可商量免费预警、尊重苏岚当前选择、处理其他地区任务，或明确放弃。内核同时限制直接锁定与伪造草稿，不能仅通过页面隐藏绕过；新局迁任事件必须与主角第20年D4的行动ID、事件ID、父来源、年份及真实历史记录一致，不能清空来源或只改执行者字段绕过。整轮提交、导入和年度结算都在写入前核验；成功招募还须有一致的兑现年代，缺证据时使用中性文字，不输出缺失日期。

## 互助仍有现实收益，但不会倒流时间

保留原行动ID、成本（D5经济3）、下一年兑现、实际互助机构及年度产出，不增加新洪水、不发回溯退款、不赠交班资格。

新合同根据实际机构区分首次设仓、已有轮值扩容、原轮值停下后的重启：

- 第10/20年兑现的互助，按现有规则为第23年的D5剩余损失减轻30%。不是全图减伤，重复轮值不叠加或相乘。新局只有仍活跃且维护大于0的互助才提供保护，维护为0不再冒充有效仓储；旧存档继续原判据。
- 第30年合同明确“后续生计”，第31年才增加互助载体。已发生损失、危机事件和第23年快照不变；零损失路线也可支持生计，不强称所有路线都在“灾后重建”。
- 扩容提供额外居民轮值与物资调配产出，不是第二层危机保护，也不能冒充学校、异源校验或地方授权。
- 每组足额维护互助的原有年度源项为政治0.10、经济0.60、科学0.10、宗教0.55。实际通道还受衰减、传播和其他事件影响，不能把源项当作净增预测。

方案、已锁定核对、兑现事件、南岸回访和结局都区分当前支持与历史损失。未模拟粮食库存、逐户需求、劳动负担或下一次洪水；这是现有持续制度产出的准确说明，不是假称新增了完整经济恢复系统。

## 停运不是从未发生

D4按真实测站状态选择同一地点的原创近景：运行、维护不足、人手缺口、停运，恢复后回到运行状态。停运保留测站轮廓、旧记录与封闭痕迹，不退回未建站档案桌。暂缺人手不自动画成房屋损坏；收费门槛与维护状态分别描述。未建站与建站失败的小档案仍保留自己的场景，不凭旗标画出测站。F6不受D4人员缺口误伤。

## 已发布存档的边界

无`aftermathRulesVersion`的既有23b99bee局继续原角色合同，包括林澈已经锁定、已提交或已经兑现的迁任。旧局不按年数、招募类型或`handoff-v1`静默升级。

对旧局晚期互助只增加当前界面的准确澄清，保持标题、描述、成本、事件ID、已记录文本及原结算结果。回归夹具来自实际发布23b99bee的`simulation.js`（blob `34535eb126ece2bfeb4f403abe50abe2fb316bb7`），只调整JSON导入路径。测试用真实旧内核生成存档，不靠从新局删除字段伪造兼容。

## 后续要验证的取舍

本轮没有通过惩罚同伴、额外加分或提高成功率来制造区别。拒绝改变可分派的任务组合，互助区分危机前准备与事后持续支持；具体机会成本与玩家理解仍需真人试玩。仓库扩容沿用原有线性源项，尚未加入容量上限与劳动供需，不能据此声称长期经济已平衡。

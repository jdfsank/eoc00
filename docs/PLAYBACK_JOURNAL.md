# 第23轮：让已发生的十年接住下一次选择

## 实际发现

改动前，年度页只保留当年最后六条记录，下一年会替换整组内容。自动播放每900毫秒推进一年，不因关键记载停留。十年回顾虽已有可靠的“上次选择／真实兑现／留下责任”卡片，但主卡只围绕上一介入窗口的行动，不保证收回此前行动跨十年形成的后果或独立里程碑。

这不是缺少事件，而是重要事件容易从正常阅读路径里消失。不能靠新增无来源的对白、把承诺写成结果，或改写历史解决。

### 两条真实新局路线

以下都从页面“确认开始新历史”开始，经真实调查、锁定、提交与每一年的推进到第40年。每一步完整世界状态均与未经修改的模拟API相等。两条路线自身均完成；辅助自动播放检查另用独立浏览器进程完成，不把辅助初始化失败算成路线失败。

共同选择：

- 第0年：主角在D4选择联合管理建站。
- 第10年：主角邀请林澈同行并安排真实继任。
- 第20年：主角在B4复核，林澈在D4安排基本公开预警。
- 第30年：主角签署共享方针，林澈在E4增加教学网络。

种子0：建站及复核成功，第23年清点的共同失效损失系数为0，最终题名为“许多人签署的历史”。第20年回顾默认只展示第11年招募与继任，五条原始记录全部折叠，第12年分站、第14年预警、第16年维护下降与收费、第20年旧现实冲突均不在默认正文。

种子6：建站与复核均失败，保留小型档案站和未完成校验记录。第21年D4兑现的是居民传讯队，没有补建测站。第23年真实清点为D4覆盖0.65、损失约0.77，其余三地覆盖0、损失1；整体精确损失系数0.9431。最终为“纸上的共同作者”。新教学与共享方针没有把早年的失败改成成功。

第30年原有回顾已经保留第23年“有损失／零损失”的概括，不能声称它完全遗漏危机。缺口是具体逐地清点、前后回应与原始依据仍需另行展开。手机390×844的改动前画面里，第23年事件卡从约631px开始，完整清点正文超过首屏；自动播放却约900ms后换年。

改动前独立自动播放观察到0→10年约9秒，每年间隔约900ms。该观察证明原节奏，不是玩家阅读速度的正式研究。

## 小而完整的呈现结构

1. 年度页优先呈现最近一条已发生转折的原始正文，保留既有复核、收费、迁任、旧人手规则的来源纠正说明。
2. 没有新记载的年份保留上一条，并明确标注它发生在哪一年，不声称今年再发生一次。
3. 同年其余关键记载不截断。完整当年记录和本段已发生转折仍可展开核对。
4. “推进到下一条记载”与自动播放都先调用真实逐年结算，再检查是否产生新记载。不预读未来事件，不用事件预计日期跳过模拟。
5. 十年回顾默认列出本段实际转折，再进入下一窗口。已有角色选择回顾与全部原始记录继续保留。
6. 类别短句只提示如何理解责任，不替代具体原文，不增加个人同意、成功、损失、伤亡或当前岗位。

## 只读模型接口

`src/playback-journal.js`不导入模拟内核，只读`state.year`、`state.phase`与`state.history`。

### getPlaybackJournal(state)

在真实播放期、10/20/30年规划边界和40年结束边界返回：

- `year/start/end/isBoundary/nextWindow`：当前公开日历。播放中的下一窗口是本段结束年；回顾中的窗口是已到达的当前年；40年为null。
- `currentRecords`：当年已公开记录，包含刚提交的行动和明确放弃，没有六条上限。
- `turns`：本十年`(start,end]`的关键记录，按年升序，同年保留原序。
- `pastTurns`：排除当前年的独立转折副本。
- `latestTurn`：最后一条转折的独立副本，缺少转折则为null。
- `notes`：遇到已到达当前现实的重复或畸形记录、整份history缺失时给出可见的缺页提示。

每个转折有`id/year/cellId/category/title/label/summary/record/sourceIds`。标题来自原记录的合法非空字符串，缺失才回退“已存记录”。`summary`为类别短句，`record`仅拣原条目的公开字段，完整原记录不改写。

公开字段白名单：`id/year/cellId/title/text/description/reason/kind/status/parentId/sourceActionId/reality/dueYear/type`。只复制自有数据属性，不执行属性getter，不读取任意RNG元数据。

类别为预警、实际清点、未完成、取消、维护变化、兑现记载、人物与旧档、新窗口问题、阶段结局和未知。

- outcome必须有success状态，failure必须有failed状态，cancelled必须有cancelled状态。
- warning/crisis/maintenance/reality/choice/ending使用真实kind，且状态为confirmed或旧记录缺省。
- 普通confirmed不是成功。类别与状态冲突、未知kind保留为“记录待核”。
- 明确failure/failed但正文缺失仍保留失败事实，正文细节未知。页面须提示没有保存正文，不新增原因、费用、损失或人物经历。
- arrival/action/pass/simulation保留在当前年原始记录中，不包装成兑现转折。

### getPlaybackRecordIds(state)

返回当前已经公开的有效历史ID，供真实年度结算前记录已知集合。

### hasNewPlaybackRecord(beforeIds, state)

只对结算后当前年新增的有效关键记录返回true。旧条目重排、重复读取、修改同ID标题、便利flag或未到日期的记录都不构成新记载。未知但真实新增的历史条目也保留阅读机会。

## 来源与不泄露未来的边界

- 先读取年份，未来行立即排除，不访问它的id、reality、正文、状态或其他字段。
- 再排除R0／其他现实和pending记录，只在已到达当前现实的候选中判定ID是否重复。未来或R0重用当前ID不改变今天的显示。
- 有效年份是0至40的整数，ID为非空字符串，历史身份唯一。已到达候选里的重复ID整组排除，不挑有利的一份。
- 不读取seed、roll、events、flags、snapshots、institutions、角色、草稿或调查材料来补写结果。
- `sourceIds`只指向该条已存history，不生成额外事件、因果关系或功劳归属。页面在真正跳转前还须验证history与events命名空间唯一性，防止跨表重号指错来源。
- 没有第23年清点记录就没有清点卡。不能只凭日期、危机flag或后来机构判断损失；已存清点原文中为零也不改成“发生了损失”。
- 模型与阅读不改世界、存档、历史、概率或结局；真正旧局继续读取原producer已有记录，不迁移、不重算旧危机。

## 验证

模型自有测试13项覆盖：有效阶段、各类别、冲突与未知、重复/未来/R0/缺页、同年九条不截断、禁止未来与私有getter、冻结输入无变异、每个返回对象独立、新旧producer逐年完整状态相等、原始旧局清点保留、自然条件取消，以及缺正文保留已存失败而不补细节。

独立QA另外覆盖真正归档producer文件哈希和封闭依赖、两代producer三条自然路线、逐年／下一记载／跳窗口的完整状态与存档对照，以及逐年期望停点。模型与独立QA组合运行49项通过（2026-11-06）。浏览器集成、布局、交互与最终整体验证另由本轮主流程记录，不能把纯模型通过等同完整UI通过。

改动前证据位于工作区独立`round23-playback-audit`目录：两条路线的逐年文本、状态对照、截图和自动播放时间观察。它们是工程审计材料，不是生产资产或外发游戏存档。

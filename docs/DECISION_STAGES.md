# 第22轮：决定、草稿与已经发生的事

## 独立检查依据

在改动前，以 Chromium 实际按钮检查第0、10、20、30年各一项方案的现场、预览、确认、返回、锁定与修改。使用320×568视口和应用内200%字号，没有横向溢出。开局联合管理确认正文高9,920px，锁定按钮文档纵坐标10,172px；同方案整轮页高10,822px。第30年学徒承接确认高4,881px。第0、10、30年预览和确认几乎重复全文，只换了阶段标题和按钮。长页并非只发生在最后一轮。

确认返回现场保持整个世界state字节一致；“修改安排”清除草稿，保留已支付的调查轮次。统一提交后仍处于原年份的playback阶段，下一次逐年操作才结算下一年。因此“已锁定结果”和“统一提交并推进十年”不能准确表达这两个动作。

这些是桌面Chromium的移动视口检查，不是真机、真人试玩或屏幕阅读器认证。上述尺寸是改动前基线，不是改动后验收结论。

## 每个阶段只讲自己的决定

- 免费方案预览：了解合同，决定是否调查；不改动原有安排。重读的方案可能已经锁定，不能一律称作“尚未锁定”。
- 锁定审阅：确认执行者、地域、即时成本、时间、关键风险和责任。只保存草稿，不支付、不生效、不揭示随机结果。
- 整轮安排：核对谁做什么、地方总成本与冲突。草稿中的收益是“若合同兑现的目标”，不是已经发生的结果。全部明确放弃仍是合法安排，不应把它变成错误。
- 统一提交：一次性支付成本并登记承诺，进入逐年演变，年份仍不变。
- 年度演变：到约定年份才判断成功或取消。以实际记录说明结果，不用今天的机构或未来结局补写。

确认页的返回动作是暂不锁定，不是取消已经提交的合同。“修改安排”撤下的是草稿；已花的调查轮次不退。条件不成立时的“合同取消”则是未来年度实际发生并留下记录的结果，不能混用。

## 人物责任与技术说明的分工

`src/decision-stage-copy.js`提供简短、面向未来的责任句。它们只提醒所选工作的人的意义，不虚构对话、已经取得的同意、个人经历或成功事件。角色、地点、成本、概率、期限和取消条件仍来自实际合同，不由新文案猜测。

技术细节可以放入可展开的完整合同，但不能用“风险详见”取代提交前必要的成本、失败或取消、不退费、真实前提。原型参数、完整维护链、来源规则无需在预览、确认和整轮页默认重复铺开。第30年主角签署方针的名额取舍由规划机会模块集中说明，责任句不再重复这段规则。

## API

- `getDecisionStageCopy(stage, state)`：stage为preview、confirm、window或playback；返回可独立使用的eyebrow、title、summary、status、caution、primaryLabel和backLabel。只读取state.phase，不改变状态；不支持的stage返回null。window遇到已提交或结束状态时使用历史只读措辞，避免旧UI路径误称未支付。
- `getLockedOutcomeLabel()`：返回“若合同兑现的目标”。
- `getActionResponsibility(actionId)`：返回一句责任提醒；未知行动使用中性通用句。不得以此替换合同正文或历史原文。

## 旧局精确保留范围

本轮是UI真相与层级调整，不是规则迁移。原生产者生成的存档必须原样保留：全部state字段，版本标记是否存在，角色、调查、草稿证据快照、事件ID与来源、标题和text、成本、概率、到期年、取消或成功状态、机构来源与源项、既有快照及终局。不得因新标签重写旧描述，尤其不得给旧承接合同补加新职责改排，不得用新覆盖规则重算旧危机。

`simulation.js`、`story.js`和旧生产者的历史原字符串不为这项改进而修改。用户界面的阶段标题可以对所有版本纠正，但旧合同全文与旧来源说明仍需可读。原文有不够精确的措辞时，附加解释与原文分开，不覆盖保存值。

## 针对性验证

单测核对四个阶段词汇、按钮与引擎真实语义一致，旧UI阶段不误称未支付，责任句不泄露数值或未来结局，并禁止新模块读取seed、事件或历史。用真正pre-tradeoffs与pre-training-workload生产者生成存档，再经当前restoreSave及新文案读取，逐字节比较状态与历史；没有删除版本字段来伪造旧局。

完整UI验收还须覆盖：确认返回和重读、已有草稿被候选方案替换前的取消、明确放弃与撤回草稿、缺证据禁用锁定、同格冲突和本地余额不足禁用提交、整轮双击不会重复扣费、提交后仍在原年、下一年成功或取消只由实际结算生成；在390/320宽与100/200%字下检查阅读顺序、触控、键盘焦点、展开后不丢失内容。最终整轮和浏览器回归由对应验收记录报告。

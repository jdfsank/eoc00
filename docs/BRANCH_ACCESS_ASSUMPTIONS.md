# 第十四轮：未来分站准入与既有事实的边界

最早公开内核 `ef841e8` 让商会来源在第12年建立的 F6 分站公开；`0a64767` 起新增覆盖模型时，同源分站改为收费，却没有独立版本标记。此前把原档在第11年导入，会得到收费分站；在第12年导入，则保留已经建立的公开分站。本轮把**未来创建**的准入规则独立出来，不改写已有事实。

## 规则与来源

- 新局明确保存 `branchAccessRulesVersion: source-branch-v1`，保持现行规则：商会来源分站收费，官署与联合来源分站公开。
- 显式 `public-branch-v1` 让之后按原建站链创建的分站公开，包括商会来源。两个支持的显式标签均优先于危机规则身份。
- 缺少分站标签时，`coverage-v1` 身份采用 `source-branch-v1`，旧整体危机身份采用 `public-branch-v1`。这是**之后结算的兼容默认政策**，不是生产者鉴别，也不是整个旧引擎的复原。读取与导入不补写版本标签。
- 原始旧档可能已由较新引擎续跑而仍没有新版标签。对尚待兑现的此类混合档，公开默认确实可能改变此前运行时会创建的收费准入；测试明确记录这一前瞻差异，不声称所有未标记档案未来与原生产者完全一致。
- `getFutureBranchAccess` 只接受三种规范建站行动 ID，或相应的 `action:0:protagonist:D4:build_*` 完整来源 ID。它不读种子、随机数、历史或机构来推断生产者。未知或近似来源返回“来源未核实”和空预测，不给它补造商会或公开来源。
- 识别规范来源 ID 只是解释这一来源的未来规则，不证明其历史真实性；不能单凭说明工具的返回值声称已有真实机构、成功事件或完整来源链。
- 未知旧来源的实际兑现保留原运行时的准入表达式作为兼容兜底，不因为新说明工具增加全局坏档拒绝。这不是新规则的来源证据。未知的**独立版本标签**仍在导入、提交、年度写入前拒绝。

## 不改变的事实

只有第12年真实成功创建分站时才采用未来规则。已保存的公开或收费分站不受后来标签影响；已停运机构、零维护、失败建站和已取消链都不会因此复活或补建。原建站、教学、待兑现分站的 ID、时点、费用、概率、来源条件与历史原文不重写，不重算旧通道、快照或危机。

公开或收费仍是准入事实，不自动给旧整体危机模型增加覆盖收益。新覆盖模型读取实际机构状态。D4 续约与 F6 准入独立，续约不直接改变既有 F6。另一个已存在的旧引擎边界仍保留：原始商会续约不打开 D4，而现行续约打开 D4；本轮不改变续约机制，也不借分站兼容声称已完整回滚。

## 验证

`tests/branch-access.test.js` 使用真实引擎生成档案，不靠删除现行字段伪造旧档。冻结的 `pre-branch-access-simulation.js` 来自已核验的 `150340873f7d4bb66ae6f479ed37374527ddf1bf` 运行时；还原唯一改动的棋盘导入路径后，Git blob 为 `13fba0e9ad50df2c4581cdd8ef757b0933890265`。原始与覆盖首版夹具的 blob 也分别校验。

原始与八个后续覆盖身份引擎分别在 0、1、2、6、7、10、11、12、13、16、20、30 年导入，逐年比较至40年的机械结果，并核对原有历史与快照不变。另测真实混合续跑、显式覆盖、已经兑现的相反准入、失败与取消、停运与零维护、续约的独立边界、未知来源兼容、非法版本的原子拒绝，以及说明的只读与隐藏信息隔离。比较结论按各条路线限定，不泛化为所有旧档可完整复原。

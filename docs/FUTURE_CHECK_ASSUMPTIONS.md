# 第十五轮：从零建立未来校验

基线为已发布 `7fd0ee703d9339f7c2ef68c63f38819c221b8d27`。本轮经济6、科学4、三轮取证及第34年期限均为可调的原型设计假设，不是原始交接规格、真实工程造价或已经过真人验证的平衡结论。

## 缺口与取舍

真实种子0路线：第0年不建站，第10年自愿招募林澈，第20年林澈培育E4轮值维护者、主角在B4调查撤离路线后授予强化停闸权。第23年损失系数0.1904，第30年有实际、已获授权的E4人手，却没有异源校验。过去这条路线没有从零建设未来校验的入口；另一路线如果第20年紧急复核失败，反而可以在第30年补做遗留校验。这不代表失败严格更优，因为历史损失不会抹除，但暴露了未来建设路径的不完整。

新局显式启用 `futureCheckRulesVersion: future-check-v1`。第30年仅B4提供独立新行动 `establish_future_check`（建立未来校验席）。不把新行动放进 `build_*` 测站家族，不创建第10年维护承诺、测站、学徒或分站链。

- 支付B4经济6、科学4。用途是新刻水尺、对照抄本、连续比对工作席，不是降低一次隐藏失败概率。
- 异常记录需2轮，B4居民当前证词需1轮。耗满执行者本窗口的3轮取证，不能借用别人的材料；外地居民证词不是B4证词。
- 占执行者一个本轮名额，第34年才核定。原 `complete_review` 仍为经济4、科学3、异常记录2轮、第32年核定，来源与条件均未放宽。
- B4已有运转中的独立方法来源（包括地方保档；保档不等于曾成功纠正危机）时，不再提供贵的重复建设；有可用失败底稿时，沿用原遗留合同。已经停运的旧机构不会复活；确实缺可用方法时可以另建，旧机构与失败记录保留。
- 第34年仍须真实运转的测站、分站、学徒或教学载体提供测量人手。来源复用严格的 `getRecoveryWorkforce`，传讯队、互助仓、档案和另一张校验桌不能冒充技术人手。
- 另一角色第30年安排培训，可在第31年到位，赶上第34年。两项用尽两个名额，因此没有第三个名额签方针。
- 届时无人，合同取消，材料与场地成本不退；不提前生成机构，也不伪造一次早年的复核失败。
- 成功才创建B4独立机构，并在事件及兑现记录中保存实际人手ID。它有正常独立机构产出，可支撑未来集中复核或跨地交班，不直接奖励结局分数。

人手、授权、异源方法、信任与方针仍分开核对。新校验只增加异源校验能力，不赠人手、授权、信任或方针，不设 `flags.review`，不重算第23年、旧快照、旧事件、原始文字或已付成本。同地多个有效载体仍只是一地，不能当跨地关系。实际选择退出且另有E4授权人手的自然路线可以得到“没有唯一守夜人”，但原损失0.1904与未覆盖地区仍保留；未签方针仍是“未签署的下一页”，共享还需真实信任。

## 来源与只读接口

行动、事件、兑现记录携带新规则版本。验证第30年执行者/地点/单名额、证据来源、完整6/4成本、确定的第34年时间、事件/行动/结果的规范ID与相互引用。成功验证实际人手、结果和唯一规范机构。更换动作名、提前年份、凭空增加人手、缺少材料、复制或搬动新机构均不能充当完成来源。人工来源边界在测试标题明确标注，不冒充可达玩法。

`getFutureCheckContracts` 提供严格验证后的待核、成功、取消来源，`getFutureCheckSources` 提供严格成功来源；默认只返回仍运转的机构，`requireActive:false` 可读已经停运的历史完成事实。`getFutureCheckPlan` 给菜单解释为何可以新建或为何应沿用旧方法。读取不会写世界、抽随机或推进年份。

整轮 `getHandoffOutlook` 把新合同列为第34年的条件合同，识别第31年培训支持，并保留未建成分支 `withoutConditionalChecks`；原 `withoutRecovery` 字段保留兼容。不把“概率1”说成无条件开席，不假定未来人手永久存续，不预测下一次洪水或结局标题。

## 旧局连续性

缺少新tag的真实旧局不自动获得新行动，不迁移规则、不改旧合同。显式未知tag、缺版本的新合同、非法来源均在导入/提交/年度结算写入之前原子拒绝。

原内核冻结在 `tests/fixtures/pre-future-check-simulation.js`，依赖的原分站准入helper也独立冻结。原 `simulation.js` blob为 `be6ec5826d6aedb3edbec770f9a8bc8ccdb414eb`，SHA256为 `92458fa080b3ba3bfc4003c943831cd0f3da1e66464a18181864dccc8ce0d679`；原 `branch-access.js` blob为 `b3e40a27d89e7a65bdcc2a9fe17f0ecd9f1b2341`。两者均用GitHub指定7fd提交的文件元数据核验，本地字节哈希一致；simulation仅改两个导入路径。

测试用该真实原内核产生存档，覆盖三个种子、四条路线、六个导入时间共72组，每年完整state和完整ending对照到40年。不是删掉新版本字段伪造旧存档。已有更早版本兼容测试继续保留。

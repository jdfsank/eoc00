# 第35轮：先读选择，再查年度原页

## 叙事目的

第30年移动端原始截图显示，十年回顾标题之后首先呈现21年、22年的完整年度记录；执行者的上次选择、结果与责任排在整段流水之后。这里需要调整阅读层级，不需要新增一页规则。把已有、经来源核实的角色回顾前置，再提供完整年度凭据，帮助玩家先记起自己作出的决定。

文书采用三个有形段落：上次的选择、这些年、留下的责任。沿用完整原文，以定义列表和独立样式钩子区分，不截断、不缩字号、不重写人物经历。标题与简介仍取现有回顾数据。来源按钮保留原来的编号、trace动作及记录ID。

## 来源与旧档边界

`renderDecadeRecollection`只呈现调用者提供的回顾，不读取世界、旗标、随机结果或现存机构。调用方继续使用已有的来源核验与终局文案适配。明确放弃、未知与缺页不能互相替换；第40年不重新许诺下一轮介入。

角色回顾不能代替全局清点。`renderDecadeSettlement`以“同一段历史里的清点”单独呈现当前十年中确实存在的一条危机原文及来源，不宣称由某角色造成，不提取或推算减损数值。唯一输入为`getPlaybackJournal`的已发生记录；只接受第30或40年的边界、当前区间内唯一的crisis转折，且原记录身份、年份、类别、现实与状态一致。正文缺失、重复或不一致时省略，不补零损失。

第40年正常日志区间为30至40年，不包含第23年。因此该组件不会把第23年重演为最近十年的清点。完整历史仍由原有档案和年度回顾负责。

## 集成与验收边界

本模块只提供结构，不改变年度流水的展开状态。整页集成需将角色文书前置，保持完整年度原文可展开，且从来源或只读回访返回时恢复原来的展开、滚动与焦点。独立清点不使用`data-journal-record`，避免同一记录出现两个导航身份。

样式钩子：`recollection-document`、`recollection-rows`、`recollection-row`、`recollection-choice`、`recollection-outcome`、`recollection-responsibility`、`recollection-sources`；清点使用`decade-settlement`、`decade-settlement-meta`、`decade-settlement-text`。

单位验证覆盖原文完整转义、原始来源目标、输入不变、真实明确放弃与缺页回顾、终局责任措辞、真实第23年清点及缺失原页不推断。整页仍需实测10/20/30/40年、单人与双人、成功与失败、旧档，以及390常规、320原生200%和桌面布局；检查第一份选择的阅读位置、完整原文、键盘展开与回程、世界与存档不变。模块单测不代表这些浏览器与视觉验收已经完成。

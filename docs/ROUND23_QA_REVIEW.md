## 验收设计

- 三种真实推进方式：逐年、下一记载、略过整十年。两个主要自然路线、两个生产者均从第 0 年走到第 40 年。每次实际推进都比较完整内存世界和保存世界 JSON，不只比较年份、关键 flags 或结局标题。
- 下一记载使用独立停点 oracle，只在真实逐年结算后查看新 history 的已发生 kind，不调用新展示模块决定预期、不读预计事件或未来快照。
- 真时钟观察建成、分站、预警、维护、复核、失败、清点、取消和边界；停下后再等待超过两个 900ms 周期，证明读者没有被后台推进。包含重复点击、离开世界/设置/档案、刷新和真实页面卸载。
- 当前简卡、当前原文、以前预警/失败/分站、十年回顾与原文来源/回访可返回原屏、年、选中地域、折叠、滚动及精确可见焦点。返回后不自动续播；刷新不伪造已丢弃的瞬时返回上下文。

## 独立诊断发现与处理

1. 未来历史行最初先读 `reality`，再检查年份；整行 `structuredClone` 还会触达与展示无关的额外 `roll` getter。真实抛错负控发现后，展示模型改为先按公开年份排除未来，再仅选取公开标量字段。冻结状态、未来行 id/reality getter、整个 events/seed/snapshots/flags/institutions/actors/cells getter 和额外历史 roll getter 均由独立单测拒绝访问。
2. 第一次原文安全接入漏了 playback current 的 `safeJournal` 参数。未来 parent 坏链的主卡入口已隐藏，点击总处理也会阻断，但原文仍错误地提供不可用追溯按钮。独立合法导入负控拒绝该版本；主工补上参数，停止旧聚合并重新冻结。不是通过删掉负控继续通过。
3. 缺正文与缺结果事实分开处理。明确的 failure/failed 仍是已知失败，未知的是缺失正文；主层明确写出没有保存正文、不补写具体结果。未知 kind 或 kind/status 不一致仍归未知，不能编成成功。
4. 来源返回最初用鼠标点击返回后检查 `focus-visible`，发现焦点和位置正确但无键盘轮廓。该情况不能冒充键盘失败或通过。最终脚本用真实 Shift+Tab 找到返回按钮，再 Enter 返回，原控件的轮廓、44px、上下界与未遮挡检查及六项拒绝负控全部保留，不在返回后强制焦点或滚动。
5. 逐张审看发现探索图在导入提示尚未消失时拍摄，提示遮挡了正文。最终 capture 等真实提示消失再截取原像素，不改生产样式、不修改图片，不将被遮挡的探索图计入正式视觉证据。

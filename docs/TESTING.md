## 手机视口、镜头与键盘交互回归

`npm run test:browser`现在顺序运行原完整流程和`scripts/interactions-test.mjs`；后者也可单独用`npm run test:interactions`运行。它使用真实Chromium DOM/Canvas、鼠标指针拖动和Enter/Tab键，不用设计稿或直接改游戏世界假装完成交互。最终63/63交互检查通过，原46项完整流程也重新通过。

- 初始主行动只有一个，位于世界页顶部，文字随选中地域、角色和游戏阶段变化。320×568、360×800、390×844、430×932下均无需滚动即可完整看到并点击；标准字号时按钮底边约246—247px。
- 320×568的200%模式，页面基准和主按钮均为32px，没有偷偷缩小按钮文字；按钮底边实测约530.31px，页面无横向溢出。采用缩短按钮措辞及保留地域/角色说明，而不是缩小可访问字号。
- 真实拖动将镜头中心从(288,136)移至(248,113)。切换通道、角色、往返现场以及改变视口后中心保持；显式“返回全图”才回到(288,173)。同一世界页重绘复用Canvas；离开世界页释放Phaser资源，返回后恢复会话内镜头位置。
- 调查后焦点落在对应的已展开材料标题，Enter开合不会重复消耗调查次数，Tab继续到下一条材料。页面跳转把焦点移到新标题或主行动；剩余调查次数有状态播报语义。
- UI操作不支付成本、不推进年份、不变更现实；取证只更新本来就属于UI的材料与预算。A1入口只打开地域历史，暂停时入口继续播放界面但不偷推进年份，结束后入口打开真实结局。聚焦状态下通过目录选择E4，镜头明确重定位到(320,152)。 另覆盖“聚焦→目录选择A1→世界页最近事件定位D4”：修复前选中D4但镜头留在(288,40)，修复后选择与镜头一起到D4的(288,136)，复用同一Canvas且不变更世界。此用例先在旧顺序下真实失败，再在修复后通过。

细节JSON：`interaction-test-results.json`，包括每个视口的按钮边界、字号、滚动位置和镜头数值。截图以`interaction-`开头。镜头拖动位置目前只在本次页面会话中保留，刷新后按已存的选中地域和聚焦模式定位。上述结果不代表真实触屏设备、浏览器缩放或屏幕阅读器认证。

- 已放弃角色曾错误显示为“已锁定”，修复为明确放弃。
- 角色名称跨场景不一致，统一为苏岚。
- 选中轮廓绘制在地物之间可能被遮挡，调整到全部地物之上。

## 治理差异与兼容回归

- 新模型由实际制度、开放程度、维护与人手产生当地覆盖；成功的官署/联合来源提供有限保护，失败标记不能冒充成功制度。三种成功治理路线产生不同的逐地危机损失和可见结局数据。
- 公开续约真正打开商会测站。免费预警复站补足接班人手；没有测站时建立真实传讯队。南岸互助仅减轻D5直接损失。完整复核、停闸、来源停运、远港继续运行和相同快照/读档确定性均有回归。
- 第23年覆盖与损失冻结，之后扩校只改变当前服务；结局分别展示两者。
- 新开局保存危机规则版本；缺版本的真实旧存档继续原整体公式。测试夹具是提交`ef841e89f06fb221f4a4fc95b65636ce434c5cc5`的原`simulation.js`，只改JSON相对导入路径，直接执行生成旧档，不用删除新版字段伪造旧格式。
- 真实旧版无建站→免费预警第21年导入，继续到23年保留0.8损失，棋盘通道逐格与旧内核一致；旧互助与停闸保留原全局组合。旧版已结算危机和历史记录保持不变。
- 旧版缺继任→成功免费预警复站，在证据齐备时修复继任标记；没有兑现事件、失败事件或停运站不会被自动修复。后来的强制迁任使信任为假，早先续约不会覆盖它。
- 详细公式、设计依据、假设标签和兼容范围见[治理与覆盖假设](GOVERNANCE_ASSUMPTIONS.md)。未实现人口分层、收费账本和独立好感系统；没有声称平衡已经验证。
